# Правила ведения проекта в Linear

Единый источник правды для людей, Claude Code и Cursor.
`CLAUDE.md` и `.cursor/rules/linear-workflow.mdc` ссылаются сюда.

Проект: **Alam releases** — установщики десктопного приложения и фид автообновлений.

## 1. Задачи (issues)

1. Любая работа начинается с задачи в Linear. Нет задачи — нет ветки и PR.
2. Заголовок: императив, коротко, без префиксов типа `[BUG]` (тип задаётся лейблом).
   Пример: `Исправить падение автообновления на Windows`.
3. Описание: **Контекст → Ожидаемый результат → Критерии приёмки** (чекбоксы).
   Для багов: шаги воспроизведения, фактический/ожидаемый результат, версия приложения, ОС.
4. Одна задача — один PR. Если задача больше ~2 дней, разбить на sub-issues.
5. Обязательные поля: **Type-лейбл**, **Area-лейбл**, **Priority**. Estimate — для всего, что берётся в цикл.
6. Приоритеты: Urgent — сломан релиз/автообновление у пользователей; High — блокирует цикл;
   Medium — по умолчанию; Low — улучшения; No priority — только в Triage.

## 2. Статусы

`Triage → Backlog → Todo → In Progress → In Review → Done` (+ `Canceled`, `Duplicate`).

- В `In Progress` — максимум 2 задачи на человека.
- `In Review` ставится, когда открыт PR.
- `Done` — только после merge (и, для релизных задач, после публикации релиза).
- Заблокированную задачу не переносят в другой статус: ставят лейбл `blocked` и пишут причину комментарием.

## 3. Лейблы

Группы (взаимоисключающие внутри группы):

| Группа | Лейблы |
|---|---|
| **Type** | Bug, Feature, Improvement, Chore, Docs, Research |
| **Area** | app, installer, auto-update, release-ci, website, infra |
| **Platform** | macOS, Windows, Linux |
| **Flag** (можно несколько) | blocked, needs-design, needs-review, breaking-change, security, regression, hotfix, good-first-issue |

Создаются скриптом `scripts/linear-setup-labels.mjs`.

## 4. Git и PR

1. Имя ветки — `git branchName` из Linear (`<user>/ALM-123-short-title`).
2. Коммиты: Conventional Commits, ID задачи в конце: `fix(updater): handle 404 feed (ALM-123)`.
3. В описании PR: `Closes ALM-123` — Linear сам двигает статусы.
4. PR не мержится без прохождения CI. Релизные PR (`release-ci`, `hotfix`) требуют ревью.
5. `breaking-change` и `security` — всегда отдельная пометка в PR и в changelog.

## 5. Релизы и автообновления

1. Каждый релиз — отдельная задача с лейблами `Chore` + `release-ci`, чеклист: сборка под все платформы,
   подпись, загрузка установщиков, обновление фида, проверка автообновления со старой версии.
2. Фид автообновления не правят вручную без задачи и ревью.
3. Откат релиза — задача с `Urgent` + `hotfix` + `regression`.

## 6. Правила для AI-агентов (Claude / Cursor)

1. Перед работой: найти задачу через Linear MCP (`get_issue`/`list_issues`). Если задачи нет — предложить создать, не начинать молча.
2. Не создавать дубли: сначала `list_issues` с поиском по ключевым словам.
3. Создавая задачу, всегда ставить Type, Area, Priority и критерии приёмки по шаблону из п.1.
4. После изменения статуса или найденной проблемы — оставлять комментарий в задаче (что сделано, ссылка на PR).
5. Найденное попутно, но вне задачи — отдельной задачей в `Triage`, а не расширением текущего PR.
6. Никогда не закрывать/отменять задачи и не удалять лейблы без явной просьбы пользователя.
7. Не вставлять в Linear секреты, токены, персональные данные пользователей.
